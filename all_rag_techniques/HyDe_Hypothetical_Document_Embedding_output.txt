🎯 LEZIONI CHIAVE:
   1. HyDE genera documenti ipotetici A RUNTIME per ogni query
      → Trasforma query brevi in documenti dettagliati
   2. Il retrieval usa l'embedding del documento ipotetico
      → Elimina il mismatch query-documento
   3. L'indicizzazione è standard (embeddings normali dei chunk)
      → La 'magia' avviene solo al momento della query
   4. Trade-off: precisione aumentata vs latenza query
      → Ogni query richiede una chiamata LLM aggiuntiva

💡 QUANDO USARE HyDE:
   ✅ Query complesse che richiedono risposte dettagliate
   ✅ Domini tecnici dove espandere la query aiuta
   ✅ Quando la precisione è prioritaria rispetto alla latenza
   ✅ Documenti lunghi e dettagliati nel vector store

⚠️  QUANDO HyDE HA MENO IMPATTO:
   - Query già dettagliate o documenti brevi
   - Necessità di latenza minima (HyDE aggiunge overhead)
   - Budget limitato per chiamate LLM (costa ad ogni query)
